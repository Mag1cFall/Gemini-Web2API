# 运行日志与请求账本

## 控制台

每条日志一行，依次为时间、级别、来源、请求编号与消息：

```text
10-14 18:03:18.452 INFO  user-example-gmail-com          账号就绪 | 层级=pro | 模型=12 | 窗口=1048576 | 耗时=1.6s
10-14 18:05:02.117 INFO  request                         #3f9a1c 请求开始 | chat | gemini-4-hydrogen | 流式=是 | 消息=3
10-14 18:05:06.645 INFO  request                         #3f9a1c 请求完成 | 200 | gemini-4-hydrogen | 4.528s | 输入 11 · 回复 92 | 20.3 tokens/s | 思考强度=low
```

- 来源为 `service`（服务）、`request`（请求）或账号 ID，账号 ID 按最长的一个对齐
- 请求编号是请求 ID 去掉 `req_` 后的前 6 位，完整 ID 在响应头 `X-Request-ID` 与管理端中
- 消息为日志名称加有序字段，写成 `名称 | 键=值 | ...`，原因与多行取值缩进写在下一行
- 输出到终端时按级别、来源与 HTTP 状态着色，设置环境变量 `NO_COLOR` 或输出重定向到文件时不着色
- `LOG_FORMAT=json` 时每行一个 JSON 对象，字段为 `time`、`level`、`msg`（日志名称）、`fields`（`key` 与 `value` 组成的有序数组）、`event`、`source`，请求事件另有 `request`

`LOG_LEVEL` 取 `debug`、`info`、`warn`、`error`，默认 `info`，可在管理端设置页即时修改。`debug` 另外输出每次上游 RPC 的名称、状态与耗时，非生成接口的访问，以及 Cookie 轮换结果。

## 请求

生成请求从开始到结束输出以下阶段：

| 消息 | 含义 |
| --- | --- |
| `请求开始` | 协议、模型、是否流式、消息数与工具数 |
| `账号开始处理` | 选中的账号与实际模型，排队时附排队时长 |
| `附件上传完成` | 附件数量、大小与上传耗时 |
| `收到首个输出` | 首个正文、思考、代码或媒体事件及等待时长 |
| `备用请求发起` | WARN：原请求等待首个输出超过阈值，用另一个账号发出同一请求；附原请求已等待时长、阈值与原账号 |
| `原请求胜出，取消备用请求` | 原请求先收到首个输出，备用请求取消 |
| `备用请求胜出` | 备用请求先收到首个输出，原请求被取代；附原请求已等待时长 |
| `原请求失败，等待备用请求` | WARN：原请求失败，结果改由备用请求给出；附备用账号与原因 |
| `账号切换` | 尚未输出时上游失败，换账号重试，下一行为原因 |
| `转入后台生成` | Deep Research 等生成转入后台，服务开始轮询成品 |
| `后台生成轮询` | Deep Research 等后台生成的轮询次数与已等待时间 |
| `回答写完函数调用后上游出错，按已收到的调用正常结束` | WARN：上游在完整的函数调用之后出错，请求按已收到的调用正常结束；附原因 |
| `请求完成` | 状态码、模型、耗时、输入、思考、回复 token、生成速度与按账号模型目录选定的思考强度 |
| `请求失败` | 状态码、模型与耗时，下一行为原因 |
| `请求取消` | 客户端断开或管理端取消时所处的阶段，状态记为 499 |

`请求失败` 的状态码低于 500（含 429）时为 WARN，500 及以上为 ERROR；`请求取消` 为 WARN。

请求在同一阶段停留 15 秒没有进展时写一条 INFO 等待日志，之后每 30 秒重复一次，每段静默都从 15 秒算起；`请求准备等待` 之后收到响应头时写 `请求准备结束`，附等待时长与状态码，`等待模型继续输出` 之后收到新事件时写 `模型继续输出`：

| 消息 | 含义 |
| --- | --- |
| `等待可用账号` | 所有可用账号的请求槽都被占用 |
| `请求准备等待` | 上传附件或发送生成请求 |
| `等待模型开始输出` | 已发出生成请求，模型尚未输出；附上游心跳数与已读取字节 |
| `等待模型继续输出` | 模型已开始输出，正在思考或生成下一段；附最近事件、心跳数与已读取字节 |

管理端活动请求与日志页显示请求当前所处的阶段：`等待账号`（预热等待账号的空闲请求槽）、`初始化停用账号`（预热停用的账号时以临时客户端读取账号状态）、`同意上传条款`（带附件的请求先确认官网的上传条款）、`上传附件`、`等待官网响应`（生成请求已发出、等待官网返回）、`等待模型开始输出`（官网已响应、模型尚未输出）、`接收输出`。

| 消息 | 含义 |
| --- | --- |
| `生成流中断，读取会话取回回答` | 普通会话的生成在回答完成前断开，改为读取网页会话取回这一轮回答，带中断原因 |
| `后台生成轮询网络错误，下次重试` | Deep Research 等后台生成读取进度时遇到网络错误，按间隔再次读取 |

非生成接口只在失败时记录：`鉴权失败`（OpenAI 与 Anthropic 为 401，Gemini 为 400 或 403）、`未知路由`（404）与 `请求被拒绝`（其他 4xx、5xx）；`debug` 级别另记每次非生成接口的 `访问`（路径、状态码与耗时）与 `删除文件`。

与请求相关的保存与清理：

| 消息 | 含义 |
| --- | --- |
| `保存响应失败`、`读取未完成的后台响应失败` | WARN：Responses 的保存响应写入或启动时读取未完成的后台响应失败 |
| `保存视频任务失败`、`保存视频会话失败`、`读取未完成的视频任务失败`、`视频缩略图保存失败` | WARN：视频任务及其网页会话写入或启动时读取失败 |
| `恢复会话`、`读取会话失败`、`清理会话失败` | 启动时从账本恢复网页会话的数量，或读取与定时清理失败 |
| `恢复冷却`、`读取冷却失败`、`保存冷却失败` | 启动时从账本恢复账号冷却的数量，或读取与保存失败 |
| `已删除网页会话`、`删除网页会话失败` | 客户端删除会话时官网会话随之删除，或删除失败 |
| `读取首事件样本失败` | WARN：首个输出备用请求的自动阈值无法从账本读取近 24 小时样本，阈值按默认值 |

## 请求账本

生成请求结束后写入 `data/requests.db`（SQLite），记录时间、协议、路径、模型、实际模型、账号、状态、耗时、首事件时间、排队时间、token 用量、工具调用数、错误与每次换号的尝试。记录保留 90 天，另按小时与本地日汇总。管理端用量页按时间范围、模型、账号、协议与结果统计请求数、成功率、延迟分位、token 与估算费用，并可导出 CSV。

估算费用按请求时刻生效的 Gemini API 付费层 Standard 单价计算，输入超过 200,000 token 时按长上下文单价计算；生成图片的回复 token 按 Gemini 3.1 Flash Image 的图片输出单价计算，每张图按长边计 747 至 2520 token；生成视频按 Gemini Omni 1.2 Flash 的视频输出单价计算，每段 10 秒视频按分辨率计 token（720p 为每秒 5,792 token）；生成音乐按 Lyria 3.5 的每首单价计算成功的请求；Gem、默认模型与 Canvas 等工具按实际回答的模型计价，没有对应单价的模型不计费用。

管理端用量页把范围内的记录导出为 CSV，列为 `time`、`id`、`response_id`、`protocol`、`path`、`model`、`provider_model`、`account`、`status`、`state`、`duration_ms`、`first_event_ms`、`queue_ms`、`input_tokens`、`reasoning_tokens`、`reply_tokens`、`total_tokens`、`tool_calls`、`error`、`attempts`。

`REQUEST_BODY_LOG=true` 时另保存最近 1000 条请求与响应正文，每段最多 64 KiB，在管理端请求详情中查看。

账本自身的日志：

| 消息 | 含义 |
| --- | --- |
| `请求账本写入失败` | ERROR：一批记录写入 SQLite 失败，带记录数与原因 |
| `请求账本写入队列已满` | WARN：写入跟不上请求结束的速度，给出丢弃的记录数 |
| `请求账本清理失败` | ERROR：每小时清理过期记录失败 |
| `请求账本已按服务器时区重建本地日汇总` | 服务器时区与上次运行不同，按新时区重建日汇总，带天数 |
| `导出请求记录失败` | WARN：用量页导出 CSV 中途失败 |
| `文件总量超过上限，删除最早的文件` | 上传文件总量超过 4 GiB，删除最早的文件 |
| `清理上传临时文件失败`、`删除遗留的上传临时文件失败` | WARN：上传过程的临时文件清理失败 |

## 日志文件

`LOG_FILE=true`（默认）时控制台的每条日志同时以同一格式、不带颜色写入数据目录下的 `data/logs/gemini-web2api.log`，每行时间带年份与时区偏移（如 `2026-10-14 18:03:18.452 +08:00`），命令行版、Docker 与桌面版相同。单个文件 10 MB 轮转，轮转文件名带本地时间，目录总量超过 `LOG_MAX_TOTAL_MB`（默认 500，不小于 20）时删除最旧的文件。两项在管理端设置页保存后立即生效。

未恢复的 panic 与运行时致命错误连同全部 goroutine 栈追加写入数据目录下的 `data/logs/crash.log`，命令行版、Docker 与桌面版相同。
